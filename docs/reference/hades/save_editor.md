# Hades I Save Editor

[#584](https://github.com/TeaganRicardo/MacGamingTrainer/issues/584) owns the independent Hades I editor. Compatibility comes from `Backend/games/hades/module.json.supportedBuild`; native semantic rows and official bilingual identities come from `save_catalog.json`. This implementation adds no product release, resident Lua or persisted Profile revision. The adapter commands are additive within the existing module protocol.

## Static artifact evidence

The investigation inspected the declared supported x86_64 `Game.macOS` executable and its bundled `Content/Scripts` and `Content/Game/Text` files. The executable SHA-256 was `f69aab08ba6d12da66252a198d3c6c6606fc9de2e1b277458fae442526a75279`, matching the module's supported artifact. Addresses below are absolute unslid addresses in that artifact; they are research anchors, never feature offsets.

REA opened an immutable copy with Ghidra 12.1.4, profile digest `c027fac311b23874c52441ed55610273dff33987b0370a0589c90be8f6d72b7a`, run `6e04b10d-9d2e-4674-be8f-b8b5f2555af3`. Full procedure discovery timed out and supplied no decompilation evidence. The session was closed. Targeted, symbol-resolved Apple LLVM 21.0.0 static disassembly supplied the native format evidence. No game process or real save tree was involved.

| Native owner | Observed representation |
| --- | --- |
| `sgg::BinaryLoadData::fromStream(FileStream*)`, `0x100061870` | Checks `SGB1` at `0x1000619f8`; computes Adler-32 over bytes after offset 8 at `0x100061a8c`. |
| `sgg::ProgressManager::Save(...)`, `0x1003d0b90` | Writes version literal 16 as four bytes at `0x1003d2ab1..0x1003d2adc`, then the fields below. Calls raw `LZ4_compress_default` at `0x1003d3189`, writes compressed length at `0x1003d31c1`, and checksum at `0x1003d342a`. |

| `sgg::adler32`, `0x100148510` | Initial a=1, b=0, modulo 65521. |

All numeric fields are little-endian. `bytes32` means uint32 length followed by raw bytes, with no terminator or UTF-8 requirement.

```
SGB1                         4 bytes
Adler32(file[8:])             uint32
version = 0x10               uint32
timestamp                    uint64
location                     bytes32
completed_runs               uint32
accumulated_meta_points      uint32
active_shrine_points         uint32
easy_mode, hard_mode         uint8 each
notable_count                uint32
notable_strings              notable_count × bytes32
map_name, next_map_name      bytes32 each
compressed_luabins           bytes32, one raw LZ4 block
```

The header before the compressed field is below `0x4000`. Uncompressed Lua is below `0x8f4000` bytes; the native destination buffer is `0x8f4000`. Compressed output is 1..`0x2fc000` bytes. The codec validates checksum, version, each length, these bounds and the absence of trailing bytes. Header byte strings use reversible surrogateescape internally and typed base64 at the JSON boundary when required.

The separate `activeProfile` naming file also begins `SGB1`, followed immediately by a uint32 string length. Its naming parser provides inventory defaults and backup labels; it establishes no `.sav` codec validity. Validation marker `.v.sav` files are excluded from editable documents. Other declared profile variants remain explicit physical choices.

## Lossless luabins and reuse boundary

`luabins_load` is at `0x10000220c`, recursive `load_value` at `0x10000236f`; `luabins_save` is at `0x100014430`, recursive `save_value` at `0x1000145bc`. The first byte counts 1..250 top-level values. Native `Main.lua` writes one root table; additional encoded values are retained.

| Tag | Payload |
| --- | --- |
| `-`, `0`, `1` | nil, false, true |
| `N` | Eight original IEEE-754 double bytes |
| `S` | uint32 length and arbitrary Lua string bytes |
| `T` | uint32 array count, int32 hash count, then their sum of ordered physical key/value pairs |

`lbs_writeNumber` (`0x10000d711`) and `lbs_writeString` (`0x10000d75d`) copy raw representations. `save_value` permits table depths 0..249 at `0x100014686`, and serializes keys and values recursively at `0x100014722` and `0x10001473a`. Native `load_value` rejects nil and NaN keys at `0x1000024d6..0x100002502`, accepts table-valued keys and applies `lua_rawset` at `0x100002523`.

Hades-owned `LuaTable` retains allocation counts and every physical entry. Bool and number keys remain distinct; numeric aliases and duplicate entries remain separate occurrences. Unmodified doubles retain their original bytes, including negative zero and NaN payloads. Unchanged documents retain their original compressed block. Edits preserve unmodified encoded values; recompression can change compressed bytes after a Lua edit. The format provides no shared-reference or cycle representation.

Opaque paths identify a workspace's document baseline, the top-level occurrence and each physical entry's key or value. A verified Apply rotates that baseline generation; an old occurrence ID cannot resolve against a shifted or replaced table. Every edit, basket mutation, target selection and Apply also requires its captured generation, including semantic/header operations. Semantic helpers require one matching native key; ambiguity leaves the occurrences editable through Advanced. Advanced supports typed set, unset, append, key edits and whole-subtree replacement, including table keys, raw byte strings and explicit IEEE-754 values. Invalid nil/NaN keys, an invalid main root, an unavailable occurrence or native size/depth limits produce a concrete error. Unknown gameplay impact produces an editable warning.

Only `Backend/core/lz4_block.py` is shared with Hades II. Both supported containers use raw LZ4 blocks with the same token/offset/extension representation; each game supplies its own byte limits and translates primitive errors. The existing Hades II codec remains the owner of its version 17/18 container and luabins policy. Its uint16 version/flags, extra header fields, smaller Lua bound, UTF-8 header policy, table-key policy and depth limit differ from Hades I. No Hades II domain schema or UI was copied into the Hades I editor.

## Persistent owners and edit meaning

`Main.lua:1008..1035` strips transient rooms, applies `RunSaveWhitelist` to older history and serializes eligible globals outside `SaveIgnores`, functions, userdata and threads. `Main.lua:1071..1081` restores saved globals while protecting ignored globals and existing functions. The editor retains the encoded state rather than reconstructing stripped runtime owners.

`save_owners.py` is the canonical registry of full native saved-global paths, ordinary-purpose descriptors and physical entity boundaries. It distinguishes globals from fields under `GameState` or `CurrentRun`; fixtures author the independently evidenced native shape and exercise every registered root. Ordinary traversal accepts described paths and source-proven entity collections, rather than inheriting arbitrary children from an otherwise known owner. Supported run summaries follow `Main.lua:933..956`; Hero fields, weapons and traits follow `RunManager.lua:1..15,1918..1931` and `TraitScripts.lua:239..267`. Known collection identities come from supported native data tables recorded in `save_catalog.json.nativeIds`; a native identity may label its own entity. Indexed run, trait and unlock records receive bilingual purpose labels. Unresolved fields, including `RoomHistory` runtime detail and unknown nested Hero fields, remain editable through Advanced with their exact typed occurrence paths.

`Tools/generate_hades_save_catalog.py` reads native text statically. It extracts the 12 paired Mirror rows, six weapons' four aspect definitions/rank bounds and official same-ID bilingual terms. Native language-independent localization aliases resolve against each language's keyword text. It also reads literal scene/line/choice tables from supported `*TextLineSets` owners in NPC, loot, room and other native data, with `TextLineSets.lua` as source evidence. English comes from displayed line `Text`; other languages use the cue ID's native dialogue localization, following `Narrative.lua:454..470` and its English fallback. Speaker identity follows explicit line/source speaker or source name; the hero's `CharProtag` maps to the native `PlayerUnit` label. Ordinary scene rows show the localized speaker/content directly. Only those visible bilingual strings enter content search; prerequisite tables and callback metadata do not. `save_catalog.json.sourceEvidence` owns the source hashes; the generator executes no game Lua.

Native identity files and full IDs enter discovery before label extraction. Structural English `InheritFrom` records without an English title remain available to each locale, so variant prophecies use their translated parent titles. Codex chapter titles follow the native `TitleText` ID. The supported-source audit resolves bilingual titles for 58/59 prophecies, 152/157 renovations, 31/40 character identities, 44/55 Mirror identities, 395/487 trait identities and all nine Codex chapters. The untitled prophecy is `DefaultQuestItem`; untitled renovation identities are `DefaultCosmeticItem`, `DefaultCriticalItem`, `GiftRack`, `LoungeItem` and `NorthHallItem`. Ordinary user-facing collections require a resolved bilingual title; the exact remaining untitled character/Mirror/trait IDs are the corresponding `nativeIds` list minus `names` keys in the generated catalog. These remain typed editable in Advanced. `nativeIds.diagnostics` records exact source declarations with `DebugOnly=true` and excludes them from ordinary traversal even when they have text. Room/encounter counter keys retain source-proven native identity labels within their purpose-described diagnostic count collections; four story flags have explicit bilingual purpose labels and seven resources use the owning resource terminology registry. Missing titles are never invented.

The active-player-facing audit finds titles for all 58 `QuestOrderData` entries, all 24 Mirror-pair members, all 24 weapon aspects and every reward in the owning Hades catalog. `GiftData`'s only untitled IDs are `DefaultGiftData` and `DefaultGodGiftData`. Untitled Mirror data IDs are `BaseMetaUpgrade`, `ExtraChanceWrathMetaUpgrade`, `HardEncounterShrineUpgrade`, `HarpyDifficultyShrineUpgrade`, `HealthDropMetaUpgrade`, `HealthEncounterEndRegenMetaUpgrade`, `HydraDifficultyShrineUpgrade`, `LimitMetaUpgrade`, `RallyMetaUpgrade`, `SpeedMetaUpgrade` and `WeaponDamageMetaUpgrade`; none is a paired Mirror choice. Rows carry separate physical `ownerId`/`groupId` and localized labels. Unknown encoded fields remain reachable in Advanced. The Changes basket revises/removes one user action and recomputes its links against the original in-memory baseline; conflicting overlapping actions are rejected before the basket changes.

## Workspace and transaction ownership

Hades' adapter owns UUID workspaces. A secure Core read pins source kind, snapshot ID where applicable, root ID, relative path, original hash and document bytes. Inventory refresh and active-profile changes cannot retarget an opened document. Targets are explicit declared physical identities, resolved independently of the source. Verified backups use Core's contained manifest reads and independent editor workspaces.

`HadesSaveEditSession` encodes and reparses a complete candidate, fsyncs a temporary file, then calls Core's selected-file replacement with its captured target path. Core captures the complete pre-write save set, creates a recoverable automatic pre-edit snapshot, detects target races, atomically installs only the selected file and checks its hash. The Hades callback rereads/decodes installed bytes and compares the exact candidate; Core checks again after the callback and during hot replacement. Unrelated files retain independent mutation ownership. A verified rollback preserves the basket. Incomplete rollback retains Core recovery evidence and permanently blocks Apply in that workspace.

On success the workspace adopts **its own verified candidate** as the in-memory baseline for successive edits, rotates `baselineGeneration` and clears the basket. The originally read source/hash remain fixed; Apply never reopens or rebases from a later external target. The receipt names the new generation, actual target, installed hash and pre-edit snapshot. Old-generation controls and queued edits are rejected before ID resolution or candidate mutation. A verified rollback retains the existing generation; an independent workspace has its own generation even over identical bytes. A deliberate Read selects a new document ownership session; replacing a document with pending changes asks to discard them. Hot disk replacement reports `runtimeReloaded=false`; a running game can retain its own state and later overwrite the file.

The frontend reuses Host `TrainerToolWindowStore` and the optional module `managedBackupEditor` factory. Reopening one tool focuses its existing model/drafts; different managed backups have different window IDs/workspaces. Native controls commit completed valid drafts; focused or rejected drafts remain visible and block Apply until completed, corrected or discarded. Requests retain their session lifecycle, workspace, document baseline and query/detail authority. Apply disables the old controls through the verified receipt and replacement with matching-generation rows; the new baseline starts on its first page. Close/quit waits for pending writes and releases only the affected workspace.
